- Pointers: I used pointers in all 4 functions that I had to implement. In addStudent(), I had to manage a pointer to the name of the new student being added, as well as a pointer to an array of pointers, pointing to the names of all of the students in the list. There is an additional pointer here to point to the array holding each student's GPA. All of these pointers point to data created on the heap, so it is dynamically managed, and must be removed at the end of the program. The other functions use similar pointers, but not as many as this first one. The pointers are mainly used for pointer arithmetic, where an integer is added to the pointer to move to another memory location in the array. This is used to "append" a new student to the list, find a specific student's GPA, and iterate through the whole list to calculate the average GPA of all students.
- Const: One place const is used in solution.cpp is in the catch clause to catch errors. Here, const makes the error message given by the "throw" keyword immutable, to ensure error message integrity. There are a few other instances of const used in the function definitons. For example in printStudent(), both pointers to the student's name and GPA are const. Like I mentioned before, these are pointers that are dynamically managed and must be freed at the end of the program, so it is important to make sure they are not changed anywhere. Losing them could leave a dangling pointer that would just take up space in memory for no reason. The double array of GPAs in averageGPA() is also const for this same reason.
- References: A few parameters to the functions in solution.cpp are references. This is because they are values that are created and managed in starter_main.cpp, and unlike const variables, must be directly edited inside these functions in solution.cpp. For example, in addStudent() there is a parameter int& size, which represents the size of the whole list. This is a reference because when a new student is added, this value needs to be incremented. But since it was created in an entirely separate file, the way to do this is by passing it by reference into this function.
- Casting: The only spot casting was used was in the averageGPA function. After calculating the average GPA, the program must return this value as a rounded integer, rather than a double. A static cast is used to convert this value from a double to an int just before returning it.
- Exceptions: There are 2 places where exceptions are used in solution.cpp, in addStudent() and averageGPA(). The issues they are there to prevent are if the user tries to add a student to the list after it is at capacity, or when the user tries to calculate the average GPA when the list is empty. These start with the "try" clause, where code that may fail is run. At the top of these try clauses, there is an if statement checking a condition to see if the 2 problematic events have occurred. If they have, the "throw" clause is there to throw an error message. Following this if statement is the rest of the function's logic, which will run normally if the error isn't thrown. Finally, there is a "catch" statement after the "try" statement. This will catch the error that was thrown and in this case print it to the terminal. This allows the program to continue running after an error is caught and managed, rather than quitting the whole program.
- Control Flow: The control flow of this program is all managed in the starter_main.cpp file. Within the main function, the first bit of control ensures the program was run properly. The program requires an in-line parameter to run, so without this parameter the program will just exit with instructions on how to properly run it. After this is the main control of the program, the do-while loop. This loop runs indefinitely until the user enters 5, the option to quit the program. Within this do-while loop is a switch statement that controls which function from soltion.cpp is run. A choice 1-5 is given by the user and depending on this choice, a function will be run or the program will quit. Within each case in the switch statement, there are break statements, that are crucial to the control flow of the switch statement. These prevent more than one switch case from running per iteration. Finally after the do-while loop is exited by the user, a for loop is run to free every pointer to every student's name. Solution.cpp has minimal control flow. It mostly consists of the try-catch clauses with one for loop and one while loop in the file, but it is mostly straightforward.
